# Test plan EC-145 (deactivate / reactivate an employee, client)

API half: `PUT /api/employees/:employeeId/active` (EcoFin-API, EC-143 and O02). Unit tests: `npm test`. e2e: `RUN_E2E=1` with the API, local Supabase and the dev server; env as in `e2e/auth.spec.ts` plus `E2E_CASHIER_EMAIL` and `E2E_CASHIER_PASSWORD` (the cashier's list login is taken from the email's local part, or `E2E_CASHIER_USERNAME`).

## Section 2 answers

1. **Existing action:** yes. The Employees screen already had Deactivate/Reactivate buttons wired to `PUT /api/employees/:employeeId/active` (O02). Gaps filled: reason always required (3–500, inline error), `<Can permission="employee.manage">`, greyed inactive rows, the action in the edit drawer (the employee detail), per-code error handling, and a mutation hook.
2. **Duplicates in the API:** one live route and one SQL function. The EC-143 controller `employees.controller.setActive` and service `employees.service.setEmployeeActive` are not mounted (dead code); the route runs O02's `staff.controller.active`. EC-143 and O02 each defined `public.set_employee_active`; migrations `20261006110350` and `20261006120000` drop the older one and keep a single merged function. Nothing changed.
3. **Contracts:** `@ziadkhaled-wb/contracts` 0.8.1 (registry, already in `package.json`) exports `EmployeeActiveSet`. No dependency change.
4. **403 `ACCOUNT_DISABLED` before this change:** the client did nothing special. Only the login page mapped it to an inline message. A deactivated employee with a live token just saw generic errors.

## Notes

- The row actions are inline buttons (O02 has no row menu component for them); the same action is also in the edit drawer.
- The cashier's "next action" in the e2e is a page reload: no button a cashier can reach in this build calls the API by itself, and a reload fires `/api/me`, the permissions and subscription calls.
- The e2e signs the seeded cashier out for a moment, so `playwright.config.ts` runs it in a project that starts after the other specs finish.
- Web CI already has an e2e job (EC-144) that runs `npx playwright test` with the seeded logins, so this spec runs there with no CI change.
