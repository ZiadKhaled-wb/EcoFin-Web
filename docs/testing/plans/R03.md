# R03 Credit profile and limit: Web test plan

**Slice:** R03 · Credit profile and limit (EC-65). **Decision:** D72 (API repo). Contracts 0.42.0.

## Tests

- `src/pages/customers/CustomerCreditCard.test.tsx` (English and Arabic): limit, exposure, available credit, suggested limit, the score bar with its four components, the behaviour numbers and the empty state ("no installment history yet"), the last limit changes; the excess over the limit in an alert and the below-minimum note; the Set limit button only with `credit.approve`; the request button with `sale.create` or `credit.approve` and never for a blocked customer; the limit dialog starts at the suggestion, needs a reason when raising, sends a trimmed body, lowering needs none, a server refusal is translated; the exception dialog sends the amount and the trimmed reason and validates both, `APPROVAL_NOT_NEEDED` is translated.
- `src/pages/customers/CreditExceptionsPage.test.tsx` (English and Arabic): the list with the stored snapshot, reasons and a link to the customer; the filter re-reads; approve confirms and sends `approve: true`; reject needs a note and sends it trimmed; a refusal is translated in the dialog; Cancel only on the requester's own pending request and it confirms first; a non-owner can't decide their own request, the owner can; no decision buttons without `credit.approve`; empty and failed loads.
- `src/config/navigation.roles.test.ts`: the new menu item (`credit.approve`) in the owner and manager snapshots.
- `CustomerPage.test.tsx` and `CustomerGuarantorsCard.test.tsx`: the credit profile is mocked now that the customer page loads it.

## By hand (walkthrough, dev servers API 3103, Web 5275)

Open a customer, set a limit (raising asks for a reason), ask for an exception as a cashier, approve it as the owner on the credit exceptions page, check the preview, switch to Arabic and check RTL.
