## Goal
A user can log in with email, or shop + username, pick a shop when the login has several, stay logged in through silent refresh, log out for real, and reset a forgotten password from the emailed link.

## Slice text (F04), client part
- Login with email or username + password
- Access token + refresh token; the client refreshes silently before expiry
- Real logout that revokes the session on the server
- Forgot-password email and a working reset-password page
**Done when (slice, client side):** a token works after refresh; logout makes the old token fail; the reset email leads to a page that changes the password.

## Contract
`@ziadkhaled-wb/contracts` `auth` module for every request/response type, and `errors` for error codes. **No local API types:** replace `src/types/auth.ts` shapes with contract imports. Server endpoints: `POST /api/auth/login`, `/select-shop`, `/refresh`, `/logout`, `/forgot-password`, `/reset-password`, `/change-password`, `GET /api/auth/me`. The server half (B6) is built in parallel against the same contract. Code against the contract, not against B6's branch.

## Behaviour
1. **Login page:** identifier + password. When the identifier isn't an email, show the shop field (`tenantSlug`; the existing `TenantSlugField` / `useTenantSlug` can be reused). Validate with the contract schema. Map error codes to translated messages (`INVALID_CREDENTIALS`, `ACCOUNT_DISABLED`, `SHOP_INACTIVE`, `SUBSCRIPTION_EXPIRED`, `TOO_MANY_LOGIN_ATTEMPTS`); never show raw server text.
2. **Shop picker:** when the login response has `requiresShopSelection`, show a picker page listing `{ orgName, tenantSlug, role }`. Choosing one calls `select-shop` and stores the active `orgId`. Every API request then sends `x-org-id`. A single shop is selected automatically.
3. **Tokens (D16):** keep the partner's zustand `persist` store. Store the access token, refresh token, `expiresAt` and active `orgId`. **Silent refresh**: schedule a refresh about 60 s before `expiresAt`, and keep the existing one-shared-refresh-on-401 logic in `src/lib/api.ts`. A failed refresh clears the session and goes to `/login`. Fix the `ASSUMPTION` comment in `api.ts` to match the contract body and response.
4. **Logout:** calls `/api/auth/logout`, then clears the store and query cache (`@tanstack/react-query`), even if the request fails.
5. **Forgot password:** identifier (+ shop when a username) → always shows the same "check your email" message.
6. **Reset password page** (`/reset-password`, reachable logged out): reads the recovery token from the Supabase link (the existing `src/lib/supabase.ts` has `detectSessionInUrl: true` and no persisted session; keep that), asks for the new password twice, calls `/api/auth/reset-password`, then sends the user to `/login` with a success message.
7. **Change password** (existing page + `RequirePasswordChanged` guard): keep it, wired to the contract.
8. **Remove** (D15) the `/activate` and `/activate-workspace` routes, their pages, and their `authApi` calls.
9. **i18n:** F09 builds the full AR/EN system later, in wave 3. For now, put every new or changed string in a minimal `src/i18n/ar.json` + `src/i18n/en.json` pair with a tiny `t(key)` helper. Don't install an i18n library; B9 will migrate these keys. No hard-coded UI text in what you touch. Keep `dir="rtl"` behaviour working.
